KL divergence, explained with a rifle

Bits per Shot

You hear a hit and walk up to the target. One hole. Was that M193 or the 77gr? KL divergence answers a precise version of that question: on average, how much does one impact tell you about which cartridge made it?

Surprise, and the gap between two surprises

Start with surprise. If you believe a hole lands at x with probability density q(x), seeing it there surprises you by -log₂ q(x) bits. Unlikely holes are big surprises. A hole in the middle of the cloud you expected is a small one.

Now suppose the truth is P but you're carrying model Q in your head. Every hole surprises you by -log₂ q(x) when it should only have surprised you by -log₂ p(x). The difference, averaged over the shots reality actually produces, is the KL divergence:

D(P‖Q) = Ex~P[ log₂ p(x) - log₂ q(x) ] = ∫ p(x) log₂( p(x) / q(x) ) dx

Read the same quantity a second way. log₂ p(x)/q(x) is the evidence one hole carries for "it was P" over "it was Q". Each bit doubles the odds. So KL is the average evidence per shot, when P really is what you're shooting.

Why the two directions disagree

KL is not a distance: D(P‖Q) and D(Q‖P) are different numbers. For two bell-shaped clouds the divergence splits cleanly into two parts. One is how far apart the centers are, measured in units of the model's spread. The other is how badly the model's shape fits the truth's shape.

This is why, when you fit a model to data, it matters which direction you minimize. Minimizing D(data‖model) punishes a model that calls real outcomes impossible, so it spreads the model wide to cover everything. Minimizing D(model‖data) punishes a model that puts mass where data never goes, so it shrinks onto one mode. Maximum likelihood is the first one.

Evidence adds up, shot after shot

Independent shots add their evidence. After n holes the total log-odds is the sum of n per-shot draws, so it random-walks upward with an average slope of exactly KL bits per shot. Every line below is one string of 25 shots.

Stein's lemma makes the slope precise. Suppose you only rarely allow yourself to mistake M193 for 77gr. Then the best possible chance of mistaking 77gr for M193 falls like 2^(-n · D(M193‖77gr)) as the shot count n grows. KL is the exponent on how fast you learn.

The lesson hides in where the KL comes from. Most of D(M193‖77gr) comes from a few M193 holes far out in the fringe, where the 77gr cloud almost never lands. Estimators that need 77gr samples near those holes to judge q(x) can't see them, so they come out low and creep up slowly as you add data.

Plain histograms are worse: one bin where M193 landed and 77gr never did makes q = 0, and log(p/0) is infinite. That's not a bug in the math. If your model says a hole is truly impossible and it happens anyway, you're infinitely surprised. Smoothing the counts hides the infinity, but the answer then depends on how much you smooth.

The Gaussian formula works well while the clouds really are bell-shaped. At 800 yards M193 is going transonic, small velocity changes swing the drop a lot, the cloud grows a long tail, and the Gaussian fit undershoots.

One more reading: wasted bits

Cross-entropy H(P,Q) = H(P) + D(P‖Q). If you built a code (or a betting strategy, or a dope card) tuned for 77gr and then fed it M193, you'd pay H(P) bits per shot that no code can avoid, plus D(P‖Q) bits for using the wrong model. KL is the price of being confidently wrong.

How this was computed

Trajectories come from a 3-DOF point-mass solver (RK4, G7 drag, ICAO sea-level air, Litz spin drift and aerodynamic jump), cross-checked against py-ballisticcalc. The solver tabulates each load's impact against muzzle velocity, and wind and dispersion are layered on top. Given a velocity, a shot is exactly Gaussian, so each cloud's true density is a Gaussian mixture over velocity, integrated with 48-point Gauss-Hermite quadrature. The exact KL is a Monte Carlo average of the log density ratio over 50,000 shots.
